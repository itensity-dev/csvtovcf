## 1. Стек

- **Astro 7.4.5** — последняя стабильная на 4.11.2026; требует Node ≥ 22.23.4. **Preact 11** для «острова»: рантайм ≈ 4 КБ gzip, привычный JSX, а инструменту нужно много состояния (сопоставление, опции, предпросмотр) — с хуками это проще, чем на Svelte. Бюджет 100 КБ на JS первого экрана при этом соблюдается с запасом.
- **TypeScript 6.0.x**, а не 7.0. TS 7 — это нативный порт на Go, а `@astrojs/check` пока поддерживает только `^5 || ^6`. Перейдём на 7, когда его поддержат инструменты Astro.
- **pnpm 10.28** (workspaces): `packages/core` — npm-пакет `csvtovcf` (MIT), `apps/web` — сайт.
- **SheetJS 0.20.3.** Владелец просил брать сборку с cdn.sheetjs.com. В сборочной среде этот хост закрыт сетевой политикой, поэтому подключён npm-алиас `xlsx: npm:@e965/xlsx@0.20.3` — это автоматическая перепубликация того же tarball с CDN (`XLSX.version === "0.20.3"`). В README и `package.json` указано, как переключиться на URL CDN одной строкой, когда хост будет доступен. Пакет `xlsx` из npm (0.18.5) не используется.
- **Кодировки:** `chardet` (MIT, порт ICU) плюс собственная оценка «кракозябр». Учитываются буквы внутри слов, символы, прилипшие к буквам, смешение письменностей в одном слове, доля акцентированных латинских букв в слове, «редкие» буквы (ð þ đ ţ). Сверху — приоритет по языку страницы и аудитории сайта. Причина: на коротких файлах (2–5 строк) голый chardet путает 1252 с Big5, 1254 с 8859-2/1257, 1256 с 1252 — это видно по тестам.
- **Телефоны:** `libphonenumber-js/max`. Полные метаданные нужны для честной валидации и для различения «мобильный / стационарный», по которому выставляется TYPE=CELL или VOICE. Модуль грузится лениво внутри Worker.
- **ZIP:** fflate (MIT, ≈ 8 КБ) вместо JSZip: JSZip распространяется под MIT OR GPL, крупнее и медленнее.
- **Обратная проверка:** ical.js 2.2 (MPL-2.0, только devDependency).

## 2. Ядро: поведение по умолчанию

- **vCard 3.0 по умолчанию.** 4.0 и 2.1 — по выбору пользователя.
- **3.0:** экранируются `\ , ; \n` во всех TEXT (RFC 2426 §5). **4.0:** `;` экранируется только в составных N/ADR/ORG — RFC 6350 §3.4 разрешает не экранировать его в остальных. Так файл совместим с парсерами, которые не снимают `\;` (так поступает, например, ical.js).
- **Folding** — на 75 октетах, по границам графем (Intl.Segmenter): эмодзи-ZWJ, флаги, кириллица и CJK не разрываются, пара `\x` тоже. Продолжение строки — CRLF и пробел.
- **2.1:** не-ASCII и переносы строк кодируются в QUOTED-PRINTABLE с `CHARSET=UTF-8`. Мягкие переносы `=` ставятся так, чтобы физическая строка была ≤ 76 символов и `=XX` не разрывался. NICKNAME и CATEGORIES в 2.1 не пишутся: в стандарте 2.1 их нет.
- **FN** никогда не пустой: части имени → организация → e-mail → телефон. У контакта только с организацией в 3.0 пишется `X-ABShowAs:COMPANY` (iOS показывает его как компанию), в 4.0 — `KIND:org`.
- **День рождения без года:** 3.0 → `BDAY:--05-17`, так пишет экспорт Google Contacts; 4.0 → `BDAY:--0517`. Совместимость с iOS нужно проверить по ручной матрице (docs/IMPORT_TESTS.md). Альтернатива Apple (`X-APPLE-OMIT-YEAR=1604`) — запасной вариант.
- **Годовщина:** 3.0 → `itemN.X-ABDATE` + `X-ABLabel:_$!<Anniversary>!$_` (формат Apple, его же читает Google); 4.0 → `ANNIVERSARY`; 2.1 → `X-ANNIVERSARY`.
- **Свои подписи** у телефонов, e-mail и адресов (например, «WhatsApp») в 3.0 → `itemN.TEL` + `itemN.X-ABLabel`, тип сохраняется.
- **Телефоны:** если в строке есть страна адреса («Deutschland», «United Kingdom», «Россия»…), она служит страной по умолчанию для этой строки. Номер без `+` и без ведущего `0`, который начинается с кода страны по умолчанию (`79161234567`, `491761234567`), трактуется как международный — Excel часто съедает `+`. `4.4E+11`, где цифры потеряны, не «восстанавливается» выдумкой: номер помечается, пользователь видит предупреждение и инструкцию.
- **Даты:** порядок день/месяц определяется по всему столбцу: значение > 12 в первой позиции значит dd/mm. Если однозначных значений нет, en → mm/dd, все остальные языки → dd/mm. `0/0/00` (пустая дата в Outlook) — пусто, без предупреждения. Нераспознанная дата не теряется: она уходит в заметку.
- **Дубли** ищутся по E.164 (или по последним 9 цифрам) и по e-mail без учёта регистра. Группы транзитивные. Слияние **выключено по умолчанию**: пользователь видит группы и включает слияние сам, потому что неожиданное объединение хуже, чем дубль.
- **Пропуск строк:** пустая строка; строка без имени, телефона, e-mail, организации и адреса; повтор строки заголовка (при склейке файлов). Каждая пропущенная строка попадает в отчёт с номером, как в Excel.

## 3. Ограничения, о которых говорим честно

- Если Excel уже сохранил `4.4E+11` в CSV, исходные цифры потеряны — их не восстановить ни нам, ни кому-то ещё. Восстанавливаем только те числа, где сохранились все значащие цифры.
- Фото контактов не переносим: в CSV/XLSX их нет.
- CJK-имена без пробела («王小明») не делим на фамилию и имя: угадывание ошибается чаще, чем помогает.
- Outlook CSV пишется с английскими заголовками. Классический Outlook в другой локали может попросить сопоставить поля вручную в мастере импорта.
