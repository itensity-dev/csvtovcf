## 1. Стек

- **Astro 7.4.5** — последняя стабильная на 4.11.2026; требует Node ≥ 22.23.4. **Preact 11** для «острова»: рантайм ≈ 4 КБ gzip, привычный JSX, а инструменту нужно много состояния (сопоставление, опции, предпросмотр) — с хуками это проще, чем на Svelte. Бюджет 100 КБ на JS первого экрана при этом соблюдается с запасом.
- **TypeScript 6.0.x**, а не 7.0. TS 7 — это нативный порт на Go, а `@astrojs/check` пока поддерживает только `^5 || ^6`. Перейдём на 7, когда его поддержат инструменты Astro.
- **pnpm 10.28** (workspaces): `packages/core` — npm-пакет `csvtovcf` (MIT), `apps/web` — сайт.
- **SheetJS 0.20.3.** Владелец просил брать сборку с cdn.sheetjs.com. В сборочной среде этот хост закрыт сетевой политикой, поэтому подключён npm-алиас `xlsx: npm:@e965/xlsx@0.20.3` — это автоматическая перепубликация того же tarball с CDN (`XLSX.version === "0.20.3"`). В README и `package.json` указано, как переключиться на URL CDN одной строкой, когда хост будет доступен. Пакет `xlsx` из npm (0.18.5) не используется.
- **Кодировки:** `chardet` (MIT, порт ICU) плюс собственная оценка «кракозябр». Учитываются буквы внутри слов, символы, прилипшие к буквам, смешение письменностей в одном слове, доля акцентированных латинских букв в слове, «редкие» буквы (ð þ đ ţ). Сверху — приоритет по языку страницы и аудитории сайта. Причина: на коротких файлах (2–5 строк) голый chardet путает 1252 с Big5, 1254 с 8859-2/1257, 1256 с 1252 — это видно по тестам.
- **Телефоны:** `libphonenumber-js/max`. Полные метаданные нужны для честной валидации и для различения «мобильный / стационарный», по которому выставляется TYPE=CELL или VOICE. Модуль грузится лениво внутри Worker.
- **ZIP:** fflate (MIT, ≈ 8 КБ) вместо JSZip: JSZip распространяется под MIT OR GPL, крупнее и медленнее.
- **Обратная проверка:** ical.js 2.2 (MPL-2.0, только devDependency).

## 2. Ядро: поведение по умолчанию

- **vCard 3.0 по умолчанию.** 4.0 и 2.1 — по выбору пользователя.
- **3.0:** экранируются `\ , ; \n` во всех TEXT (RFC 2426 §5). **4.0:** `;` экранируется только в составных N/ADR/ORG — RFC 6350 §3.4 разрешает не экранировать его в остальных. Так файл совместим с парсерами, которые не снимают `\;` (так поступает, например, ical.js).
- **Folding** — на 75 октетах, по границам графем (Intl.Segmenter): эмодзи-ZWJ, флаги, кириллица и CJK не разрываются, пара `\x` тоже. Продолжение строки — CRLF и пробел.
- **2.1:** не-ASCII и переносы строк кодируются в QUOTED-PRINTABLE с `CHARSET=UTF-8`. Мягкие переносы `=` ставятся так, чтобы физическая строка была ≤ 76 символов и `=XX` не разрывался. NICKNAME и CATEGORIES в 2.1 не пишутся: в стандарте 2.1 их нет.
- **FN** никогда не пустой: части имени → организация → e-mail → телефон. У контакта только с организацией в 3.0 пишется `X-ABShowAs:COMPANY` (iOS показывает его как компанию), в 4.0 — `KIND:org`.
- **День рождения без года:** 3.0 → `BDAY:--05-17`, так пишет экспорт Google Contacts; 4.0 → `BDAY:--0517`. Совместимость с iOS нужно проверить по ручной матрице (docs/IMPORT_TESTS.md). Альтернатива Apple (`X-APPLE-OMIT-YEAR=1604`) — запасной вариант.
- **Годовщина:** 3.0 → `itemN.X-ABDATE` + `X-ABLabel:_$!<Anniversary>!$_` (формат Apple, его же читает Google); 4.0 → `ANNIVERSARY`; 2.1 → `X-ANNIVERSARY`.
- **Свои подписи** у телефонов, e-mail и адресов (например, «WhatsApp») в 3.0 → `itemN.TEL` + `itemN.X-ABLabel`, тип сохраняется.
- **Телефоны:** если в строке есть страна адреса («Deutschland», «United Kingdom», «Россия»…), она служит страной по умолчанию для этой строки. Номер без `+` и без ведущего `0`, который начинается с кода страны по умолчанию (`79161234567`, `491761234567`), трактуется как международный — Excel часто съедает `+`. `4.4E+11`, где цифры потеряны, не «восстанавливается» выдумкой: номер помечается, пользователь видит предупреждение и инструкцию.
- **Даты:** порядок день/месяц определяется по всему столбцу: значение > 12 в первой позиции значит dd/mm. Если однозначных значений нет, en → mm/dd, все остальные языки → dd/mm. `0/0/00` (пустая дата в Outlook) — пусто, без предупреждения. Нераспознанная дата не теряется: она уходит в заметку.
- **Дубли** ищутся по E.164 (или по последним 9 цифрам) и по e-mail без учёта регистра. Группы транзитивные. Слияние **выключено по умолчанию**: пользователь видит группы и включает слияние сам, потому что неожиданное объединение хуже, чем дубль.
- **Пропуск строк:** пустая строка; строка без имени, телефона, e-mail, организации и адреса; повтор строки заголовка (при склейке файлов). Каждая пропущенная строка попадает в отчёт с номером, как в Excel.

## 3. Ограничения, о которых говорим честно

- Если Excel уже сохранил `4.4E+11` в CSV, исходные цифры потеряны — их не восстановить ни нам, ни кому-то ещё. Восстанавливаем только те числа, где сохранились все значащие цифры.
- Фото контактов не переносим: в CSV/XLSX их нет.
- CJK-имена без пробела («王小明») не делим на фамилию и имя: угадывание ошибается чаще, чем помогает.
- Outlook CSV пишется с английскими заголовками. Классический Outlook в другой локали может попросить сопоставить поля вручную в мастере импорта.

## 4. Сайт и URL

- **Структура URL.** Английский в корне, языки в подпапках: `/es/`, `/pt-br/`, `/id/`, `/tr/`, `/de/`, `/fr/`, `/ru/`. **Главная языка — это и есть конвертер CSV→VCF** (`/es/`, а не `/es/convertir-csv-a-vcf/`): иначе две страницы конкурировали бы за один запрос. Остальные слаги переведены под местные запросы (`/es/convertir-excel-a-vcf/`, `/tr/excel-vcf-rehber/`, `/id/convert-excel-ke-vcf/` …). Полный список слагов — в frontmatter `url` каждой страницы.
- **pt-BR живёт в `/pt-br/`, а не в `/pt/`:** тексты бразильские (celular, planilha, CEP, WhatsApp), а `/pt/` останется для португальского варианта.
- Завершающий слеш везде (`trailingSlash: 'always'`). Markdown-версия — тот же путь с `.md` (`/excel-to-vcf.md`, главная — `/index.md`).
- **Демо уникально для каждой страницы и языка:** свои имена, форматы номеров, даты и настоящие заголовки источника (немецкие, французские и русские заголовки Outlook на соответствующих страницах). Демо рендерится при сборке тем же движком, что работает в браузере.
- **Язык публикуется, только когда готовы все 19 страниц** (`allPages()`), а CI запускает `scripts/check-i18n.mjs`. Скрипт проверяет ключи, плейсхолдеры, длину title и description, TODO, внутренние ссылки и совпадение числа шагов и вопросов FAQ с английским.

## 5. Безопасность и приватность

- **CSP.** Встроенный в Astro 7 `security.csp` пишет на каждую страницу `<meta>` с хешами inline-скриптов и стилей; `connect-src 'self'`. Caddy добавляет заголовок с тем, что нельзя передать через meta: `frame-ancestors 'none'`, `object-src`, `base-uri`, `form-action` и тот же узкий `connect-src` из `CSP_CONNECT`. `script-src` в заголовке намеренно нет: иначе он перебил бы хеши из meta.
- COOP/COEP не включены (так требовал бриф).
- Данные пользователя живут только в Web Worker. В UI приходят только страница карточек (12 штук) и отчёт. Скачивание идёт через `Blob` → `<a download>`.
- **Service worker** кеширует собственный код, стили и шрифты; страницы — по принципу «сначала сеть». Пользовательские файлы в сеть не уходят, поэтому кешировать нечего. Найденная ловушка: `caches.match` без `ignoreVary` не находил модульные импорты из Worker и шрифты, у которых есть заголовок `Origin`. Исправлено и покрыто тестом `offline.spec.ts`.
- Плашка «есть версия на вашем языке» зафиксирована внизу экрана: так она не сдвигает вёрстку (CLS).
- Access-лог хранится только на edge-Caddy VPS (`roll_keep_for 336h` = 14 дней, как написано в Privacy). Контейнер access-лог не пишет.

## 6. Docker

- **Бинарник Caddy 2.11.8 весит 51 МБ, образ `caddy:2-alpine` — 92 МБ.** Минимальная сборка Caddy только из нужных модулей дала 53,7 МБ: ядро тянет TLS/ACME и OpenTelemetry. Поэтому итоговый образ — `alpine` + официальный бинарник Caddy, сжатый **UPX** (`apk add upx` из официального репозитория Alpine), плюс сайт. Это выбор по размеру; запуск и раздача файлов в Caddy не меняются.
- Локально (в этой песочнице репозиторий Alpine закрыт) образ собран с `UPX=0`: несжатые слои ≈ 65 МБ при 5,5 МБ сайта только на английском. Healthcheck, заголовки, brotli и 404 проверены. С UPX и всеми 8 языками (`dist` ≈ 25 МБ) ожидается ≈ 45–50 МБ. CI проверяет `≤ 60 МБ` и падает, если больше.
- Контейнер работает от непривилегированного пользователя (uid 10001), с `read_only` ФС, `cap_drop: ALL`, `no-new-privileges`. Порт 8080, HEALTHCHECK `/healthz`.
- Сторонние образы с UPX не используются: это риск для цепочки поставок.

## 7. Шрифты и Astro 7

- Шрифты подключены через `@fontsource`, используются только woff2 (`.woff` удаляются в Docker-сборке). Preload — одно начертание основного подмножества для языка страницы: latin; для `tr` ещё latin-ext; для `ru` — cyrillic.
- В Astro 7 Markdown по умолчанию обрабатывает новый процессор Sätteri; rehype-плагины без `@astrojs/markdown-remark` не работают. Поэтому `tabindex="0"` для `<pre>` (прокручиваемые блоки кода, WCAG 2.1.1) проставляется в `scripts/postbuild.mjs`.
- Подсветка синтаксиса выключена: тема Shiki красила примеры vCard в тёмный цвет, это вне стиля.

## 8. Переводы

- Переводы делали 7 параллельных агентов по одному заданию: локализация, а не перевод; местные формулировки запросов; названия пунктов меню как в локализованных iOS, Android и Outlook; популярные в стране марки телефонов; запрет маркетинговой лексики. Названия пунктов меню, в которых агент не был уверен, даны на местном языке с английским оригиналом в скобках. **Их стоит сверить на устройствах при прохождении `IMPORT_TESTS.md`.**
- Переводчики нашли и исправили три фактические ошибки английского исходника: «первые шесть случаев» в статье о кракозябрах; «два-три символа» при чтении Windows-1252 как UTF-8 (на самом деле `�`); пример `07911 123456` с пробелами, который Excel оставил бы текстом. Английский текст исправлен.
- Заголовки Google CSV и метки (`Mobile`, `Work`) везде оставлены английскими: Google, судя по всему, их не переводит, но это не проверено.

## 9. Не сделано / на потом

- Скриншоты экранов импорта на реальных устройствах для гайдов: нужны iPhone, Pixel, Samsung и Outlook. Шаги и файлы для этого есть в `IMPORT_TESTS.md`.
- Страницы v1.1 (`/vcf-to-csv`, `/vcf-to-excel`, `/vcf-viewer`, `/merge-vcf`, `/split-vcf`, `/vcf-editor`, `/contacts-cleaner`). Ядро к ним готово частично: есть экспорт в CSV, дубли и нормализация; нужен парсер vCard.
- Языки фазы 2 (it, pl, vi, ar): вёрстка на логических свойствах, Plex Sans Arabic подключён по `unicode-range`, у `LangMeta` есть `dir`. Нужны словари, страницы и проверка RTL.
- Outlook CSV пишется с английскими заголовками. Для немецкого и французского Outlook можно добавить локализованные заголовки, когда будут подтверждены точные строки экспорта.
